Local LM Studio Evaluation

Evaluating local model candidates and multi-pass chains with ScreamingFace

Author

Gestaltface

Published

October 23, 2026

1 Overview

This walkthrough documents the local smoke test in xp/lmstudio_eval.py. It connects a local LM Studio inference server (http://127.0.0.1:1234/v1) with the ScreamingFace evaluation runtime on medxpert. The script defaults to one question and the solo candidate only; it is a connectivity check, not an accuracy comparison. For the broader research scripts, see the experiment guide.

2 Environment & Server Setup

Sync the project environment with uv sync --extra dev. Start the LM Studio server with a model loaded, then prepare the benchmark and start ScreamingFace with its local-model overlay enabled:

uv run screamingface prepare medxpert
AIGW_LOCAL_ENABLED=true uv run screamingface up

If the stack is already running, use AIGW_LOCAL_ENABLED=true uv run screamingface restart to apply the changed Gateway setting. Set the SDK’s Engine and Scoreboard endpoints in the shell used for evaluation:

export SCREAMINGFACE_ENGINE_URL=http://127.0.0.1:9108
export SCREAMINGFACE_SCOREBOARD_URL=http://127.0.0.1:9106

3 Model Discovery & Selection

The script discovers local models exposed through the ScreamingFace overlay (local/* prefix) and automatically picks the target model using fuzzy matching:

#| eval: false
import screamingface as sf
import screamingface._environment
from tk.r.openmined import common as clib

screamingface._environment.ipykernel_loaded = lambda: False
if hasattr(sf.report.Report, "_ipython_display_"):
    del sf.report.Report._ipython_display_

print(f"screamingface {sf.__version__} ready.")

# Discover models mirrored from LM Studio (http://127.0.0.1:1234/v1/models)
local_models = [m.id for m in sf.models.list() if m.id.startswith("local/")]
assert local_models, "expect lmstudio + ScreamingFace w/ AIGW_LOCAL_ENABLED=true."

ACTIVE_MODEL = "local/google/gemma-4-e4b"
closest = clib.closestname(ACTIVE_MODEL, local_models)
ACTIVE_MODEL = closest[0]
print(f"Using active model: {ACTIVE_MODEL}")

4 Candidate Architectures

We define two candidate approaches to compare single-model generation against multi-pass refinement:

4.1 Recipe 1: Solo Local Model

Direct generation using the selected local model:

#| eval: false
solo = sf.Model(ACTIVE_MODEL, name="solo-local")

4.2 Recipe 2: Two-Pass Self-Refinement Chain

A pipeline where the first pass drafts an initial answer, and a second pass reviews and verifies it:

#| eval: false
chain = sf.Pipeline(
    [
        sf.Model(ACTIVE_MODEL, name="draft"),
        sf.Model(
            ACTIVE_MODEL,
            prompt="Review and verify this medical answer:\n\n{context}\n\nFinal answer:",
        ),
    ],
    name="local-refine-chain",
)

5 Benchmark Execution

Evaluations are triggered via sf.evaluate:

#| eval: false
BENCHMARK = "medxpert"
LIMIT = 1

candidates = [solo]  # Add `chain` to benchmark multi-pass refinement

print(f"Running evaluation on {BENCHMARK=} (limit={LIMIT})...")
report = sf.evaluate(candidates, benchmark=BENCHMARK, limit=LIMIT)

6 Results & Output Inspection

The benchmark outputs candidate scores, costs, and individual test cases:

#| eval: false
print("\n" + "=" * 60)
print(f"{'Candidate':<30} | {'Score':^10} | {'Cost':^12}")
print("-" * 60)
for c in report.candidates:
    score = f"{c.score:.3f}" if c.score is not None else "N/A"
    cost = "$0.00 (local)"
    print(f"{c.name:<30} | {score:^10} | {cost:^12}")
print("=" * 60)

for candidate in report.candidates:
    print(f"\nOutputs for {candidate.name}:")
    for case in candidate.cases:
        score = case.grade.score if case.grade else 0.0
        status = "PASS" if score and score > 0 else "FAIL"
        clean_output = (case.output or "").strip().replace("\n", " ")[:120]
        print(f"  [Case {case.case_id}] {status} (score={score}): {clean_output}...")

## Overview

This walkthrough documents the local smoke test in [`xp/lmstudio_eval.py`](https://github.com/tkukurin/gestaltface/blob/main/xp/lmstudio_eval.py). It connects a local [LM Studio](https://lmstudio.ai/) inference server (`http://127.0.0.1:1234/v1`) with the [ScreamingFace](https://screamingface.ai/) evaluation runtime on `medxpert`. The script defaults to **one question and the solo candidate only**; it is a connectivity check, not an accuracy comparison. For the broader research scripts, see the [experiment guide](experiments.qmd).

## Environment & Server Setup

Sync the project environment with `uv sync --extra dev`. Start the LM Studio server with a model loaded, then prepare the benchmark and start ScreamingFace with its local-model overlay enabled:

```bash
uv run screamingface prepare medxpert
AIGW_LOCAL_ENABLED=true uv run screamingface up
```

If the stack is already running, use `AIGW_LOCAL_ENABLED=true uv run screamingface restart` to apply the changed Gateway setting. Set the SDK’s Engine and Scoreboard endpoints in the shell used for evaluation:

```bash
export SCREAMINGFACE_ENGINE_URL=http://127.0.0.1:9108
export SCREAMINGFACE_SCOREBOARD_URL=http://127.0.0.1:9106
```
